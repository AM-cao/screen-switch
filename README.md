# ScreenSwitch · 屏幕快速切换

[English](README.en.md)

两台电脑共用一块显示器（还可以再接游戏机等设备）时，在任何一台电脑的菜单里点一下就能切换显示器的输入源；两台电脑会自动跟着调整自己的桌面，窗口和鼠标不会再跑到看不见的屏幕上。

两台电脑可以是 Windows + Mac、两台 Windows 或两台 Mac。

## 为什么需要它

显示器切到另一个输入源后，大多数显示器并不会断开与原来那台电脑的连接。原来那台电脑仍然以为显示器连着，桌面继续扩展在这块看不见的屏幕上：新窗口、弹窗、鼠标都可能跑过去找不回来。另外，很多显示器只接受当前输入口发来的 DDC/CI 指令，没在显示的那台电脑没法用软件把显示器切回来。

ScreenSwitch 在两台电脑上各运行一个常驻程序：

- **一键切换**：托盘 / 菜单栏菜单里把显示器切给对方电脑、切给某个设备（每个设备有自己的名字和菜单项），或者拿回本机。也可以自己设快捷键（默认没有）。
- **自动跟随**：每台电脑定时通过 DDC/CI 读取显示器当前的输入源，判断显示器是不是正在显示自己。被切走时，把显示器设为本机另一块屏的镜像（不移除，这样之后还能继续读 DDC）；切回来时恢复原来的排列。用显示器按钮手动切换也会跟随。
- **先直接切，不行再请对方代切**：拿回时先自己向显示器发指令；显示器只听当前输入口的（多数如此），就通过 SSH 请正在显示的那台电脑代为切换。
- **切换前先通知对方**：切给对方之前，先让对方恢复它的布局，显示器切过去时直接就是对方的桌面，不会先闪一下镜像画面。
- **两种“拿回后的布局”**：扩展（两块屏都用），或只用共享显示器（关闭本机的另一块屏）。
- **自动记住排列**：在系统设置里调整了屏幕排列，会自动记住，以后拿回时都恢复成这样。

## 支持的组合

每台电脑可以只接共享显示器，也可以另带一块自己的屏（台式机的副屏、笔记本自带屏，或 Mac 的另一块外接屏）：

| 这台电脑的屏 | 显示器被切走时 | 显示器切回来时 |
|---|---|---|
| 共享显示器 + 另一块屏 | 共享显示器变成另一块屏的镜像 | 恢复扩展，或只用共享显示器 |
| 只有共享显示器 | 不调整布局 | 不调整布局 |

哪些情况在真机上测过：

| 情况 | 状态 |
|---|---|
| Windows（共享显示器 + 副屏）配 MacBook（开盖），显示器只认当前输入口 | ✅ 作者日常使用 |
| 只有共享显示器的 Windows | ⚠️ 只有自动测试 |
| MacBook 合盖使用 | ⚠️ 只有自动测试 |
| 只有共享显示器的 Mac（Mac mini、Mac Studio） | ⚠️ 只有自动测试 |
| Mac 的另一块屏是外接屏 | ⚠️ 只有自动测试 |
| 两台 Mac 互相切换 | ⚠️ 只有自动测试（两个实例共用一块假显示器） |
| 两台 Windows 互相切换 | ⚠️ 只有自动测试（同上） |
| 显示器在非当前输入口上也接受指令（直接切换） | ⚠️ 只有自动测试 |
| Windows 的两块屏分属两块显卡（常见于笔记本） | ⚠️ 只有自动测试 |

如果你的组合在“只有自动测试”里，欢迎试用后提 issue 告诉我们结果。

不支持：三台及以上电脑；多块共享显示器；一台电脑上三块及以上的屏；Linux；Intel 芯片的 Mac。

## 适用条件

- **共享显示器**：支持 DDC/CI 并已在显示器菜单（OSD）里打开，能通过 VCP 0x60 切换输入源。部分 LG 型号不接受标准的 0x60，不支持。
- **线路要能传 DDC**：很多扩展坞、转接头、DisplayLink、KVM 不传 DDC，电脑最好直连显示器。
- **Windows**：Windows 10（1809 或更新）或 Windows 11，64 位。系统自带的 .NET Framework 4.x 和 OpenSSH 就够，不用装开发工具。
- **Mac**：Apple 芯片，macOS 13 或更新。需要 Homebrew（安装 m1ddc、displayplacer）和 Xcode Command Line Tools（编译菜单栏程序）。
- **网络（可选）**：两台电脑在同一个局域网，互相能 SSH（Windows 开 OpenSSH 服务器，Mac 开“远程登录”）。不配网络也能用，只是在没在显示的那台电脑上拿回时，要按显示器按钮（显示器接受直接切换的除外）。让对方请 Windows 代为切换时，Windows 账户要在 Administrators 组。
- **界面语言**：目前只有中文。

## 工作原理

```
电脑 A：ScreenSwitch  <── SSH ──>  电脑 B：ScreenSwitch
     │ 输入口 1                          │ 输入口 2
     └──────────>    共享显示器   <───────┘
                         ▲ 输入口 3、4…
                    游戏机等设备
```

- **判断归属**：读 VCP 0x60（当前输入源），读到本机所接输入口的编码，就说明显示器在显示本机。
- **让出**：把共享显示器设为本机另一块屏的镜像（Windows 用 CCD API，Mac 用 displayplacer）。不移除显示器，这样仍能读 DDC，知道它什么时候回来。
- **拿回**：恢复保存的排列，或者只用共享显示器。
- **两台电脑之间**只通过 SSH 调用对方的几条受限命令：`request give peer`（请对方切给我）、`request give code <n>`（请对方切给某个设备）、`request take`（告诉对方显示器马上切过去）、`request info`（问对方的名字、编码和设备）。两边的公钥都被限制在一个“命令网关”上，拿不到 shell。协议细节见 [docs/design.md](docs/design.md)。

## 安装

两台电脑各装一次，装的时候让共享显示器正显示这台电脑。安装都会进入一问一答的设置：自动找到共享显示器、读出本机所接输入口的编码，再问本机的名字、对方电脑的地址和游戏机等设备。

- **Mac**（[mac/README-mac.md](mac/README-mac.md)）：`brew install m1ddc displayplacer`，然后在 `mac/` 目录运行 `./install.sh`。
- **Windows**（[README-windows.md](README-windows.md)）：运行 `install.cmd`，再运行 `%USERPROFILE%\ScreenSwitch\ScreenSwitchCli.exe setup`。

**互相授权（可选）**：设置时会打印本机的公钥和要在对方电脑上执行的命令。对方是 Mac 时运行 `~/screenctl/screenctl.sh authorize "<公钥>"`；对方是 Windows 时在管理员 PowerShell 里运行 `setup-sshd.ps1 -PeerPubKey "<公钥>"`。两份说明里都有逐步操作。

**输入口的编码**是显示器给每个输入口编的数字，软件切换时发的就是它。常见的是 15 = DP 1（不少显示器的 USB-C 也用它）、16 = DP 2、17 = HDMI 1、18 = HDMI 2，但各家显示器不完全一样。电脑的编码由程序自己读出；游戏机等设备的编码按接口对照上面的数字填，填错了切不过去，用 `setup devices` 改掉即可。

## 使用

托盘 / 菜单栏菜单：

| 本机状态 | 菜单项 |
|---|---|
| 显示器在本机 | 切给 <对方的名字>；每个设备一项“切给 <设备名>” |
| 显示器不在本机 | 拿回主屏；每个设备一项 |

本机另有一块屏时，菜单里还有“拿回后的布局”“自动记住屏幕排列”。快捷键默认不注册，需要的话在配置文件里填，两份说明里有写法。

## 已知限制

- 显示器停在游戏机等设备上时，只认当前输入口的显示器没法用软件切回来，只能按显示器按钮。
- 切到没有信号的输入口时，有的显示器不会自动跳回，会一直黑屏，直到按显示器按钮。所以菜单上提示“请先打开设备”。
- 两块同型号的显示器分不开。
- 让出时两边系统都可能自动开启“勿扰”（macOS 镜像显示器时；据微软文档，Windows 11 默认在“复制显示器”时也会），提示可能只出现在通知中心。
- Mac 的“只用共享显示器”模式用到了 macOS 未公开的 `CGSConfigureDisplayEnabled` 来关闭笔记本屏，未来的 macOS 版本可能失效。
- 有代理软件接管 `.local` 域名（fake-IP）时，SSH 连不到对方，要单独放行，两份说明的常见问题里有处理办法。

## 安全

- 两台电脑之间只用 SSH 调用对方的 `request …` 命令。两边的公钥都被限定为强制命令入口 `ssh-gate`，只放行这几条命令，拿不到 shell，也不能端口转发。
- Windows 的 `setup-sshd.ps1` 会：安装并启动 OpenSSH 服务器；关闭这台电脑**所有账户**的 SSH 密码登录（只允许密钥）；把 22 端口的防火墙规则限定为专用网络的同一网段；把对方的公钥加进 `administrators_authorized_keys`（原有的其他公钥保留，并先备份）。运行前请确认这些改动你能接受。
- Mac 需要打开“远程登录”，建议在“系统设置 → 通用 → 共享 → 远程登录”里只允许当前用户。`authorize` 只替换同一把公钥原有的条目，其他条目保留。
