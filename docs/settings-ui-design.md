# 设计：图形设置界面、统一菜单与 Agent 安装

状态：已确认，待写实施计划。本文是两端共同的规范；协议、配置格式见 [design.md](design.md)，本文不改动它们。

## 1. 目标

- 两端（Windows 托盘、Mac 菜单栏）的右键菜单统一成同一套，只放每天要用的东西。
- 两端各有一个图形设置窗口；第一次启动时以分步向导出现，用户不必碰命令行和配置文件。
- 给 AI 助手（Agent）一份通用的安装说明 `AGENTS.md`，以及一套不用一问一答、能直接带参数执行的命令。
- 界面中英双语，跟随系统语言。

不做：配对码等新的配对方式（两台电脑互相授权仍用复制粘贴公钥）；新的跨机命令；改变 `config.json` / `config.sh` 已有字段的含义或格式；默认快捷键。

## 2. 总体做法

两端各用系统自带的界面库做原生界面，不加依赖：

- Windows：做在 `ScreenSwitch.exe` 里，用 WinForms，编译方式不变（系统自带的 `csc.exe`）。
- Mac：做在现有的菜单栏程序里，用系统自带的界面框架。

两端靠本文和同一份文字表（第 8 节）保持一致：菜单项、向导每一页、设置窗口每一项、文字都相同；只有一端才有的项，另一端不显示。

界面只负责显示和转发。设置的读写、检测、配对等逻辑放在两端各自的"命令层"里（第 7 节），图形界面、命令行问答 `setup`、Agent 用的命令都调用同一套逻辑。

## 3. 右键菜单

主屏不在本机时：

```
拿回主屏
切给 Switch
──────────────
扩展屏幕          ✓
只用主屏
──────────────
设置…
退出
```

主屏在本机时，第一项换成"切给 <对方的名字>"，其余相同。

规则：

- **没有状态行**。主屏在不在本机靠图标（亮 / 灰）看。
- **样式**：所有文字左对齐，左边不留勾选列；选中项的对号放在文字右边，靠右对齐。Mac 系统菜单默认把对号画在左边，需要自己画。
- **切换项**：第一项随状态变——在本机时"切给 <对方>"，不在时"拿回主屏"；没有配置对方电脑时不显示"切给 <对方>"，"拿回主屏"一直都有（显示器肯接受直接写入时可以切回来）。之后每个已登记的设备一项"切给 <设备名>"。刚装好、没有登记设备时没有设备项。
- **扩展屏幕 / 只用主屏**：二选一，当前选中的打勾，点另一项即切换；主屏在本机时立刻生效，不在时下次拿回生效。只有主屏时不显示；Mac 的另一块屏是外接屏时只有"扩展"一种，也不显示。
- **快捷键**：只有用户在设置里自己设了，对应菜单项右边才显示。默认一个都没有，也不推荐组合。
- **切换进行中**：切换项变灰，防止连点。
- **需要用户处理的问题**（快捷键被占用、后台程序没在运行、Mac 通知权限没开等）：图标右下角加小感叹号，菜单最上面多一行说明，点它打开设置窗口对应的位置。没有问题时这一行不出现。
- 原来菜单里的"拿回后的布局"标题、"自动记住屏幕排列"、"立即保存当前排列 / 重新保存当前布局"、"打开日志"移到设置窗口。

英文：Take back main screen / Switch to <name> / Extend displays / Main screen only / Settings… / Quit。

## 4. 首次启动向导

还没设置过时（Windows：`mainEdid` 是占位符；Mac：没有配置文件），程序启动后自动打开向导。底部"上一步 / 下一步"。中途关掉不写配置，下次启动再打开，已填内容保留。最后一页点"完成"才写入。

1. **欢迎**：两句话说明软件做什么；提醒"开始前，请用显示器上的按钮把主屏切到这台电脑"。
2. **主屏**
   - 列出已连接的显示器，每块是否能用软件控制（DDC/CI）。
   - 只有一块能控制时自动选中；有几块时让用户点选（另一块屏也应答 DDC 的情况常见）。
   - 一块都不能控制：说明可能的原因（显示器菜单里没开 DDC/CI；线路、扩展坞不传 DDC；主屏此刻没在显示这台电脑），给"重新检测"按钮，停在这一页。
   - 自动显示：本机接在哪个口（例如"这台电脑接在 DP 2"）；有没有另一块屏（例如"主屏切走时，桌面放到 <型号> 上"）；三块及以上的屏时说明不支持，停在这一页。
3. **输入口**
   - 读主屏的 capabilities，列出 VCP 0x60 支持的取值，一口一行，带标准名称（15 = DisplayPort 1、16 = DisplayPort 2、17 = HDMI 1、18 = HDMI 2，其余只显示编码）。
   - 每行选它接的是什么：这台电脑（自动填好，不能改）/ 对方电脑 / 设备（填名字）/ 没接。
   - 读不出清单时，用户点"添加输入口"手动填编码。说明文档里讲清楚各口编码的对应关系。
4. **对方电脑**（可以跳过）
   - 名字、系统（Windows / Mac）、地址（主机名或 IP）、用户名。
   - "这台电脑的公钥"和"复制"按钮，说明"把它粘贴到对方电脑设置窗口的'对方公钥'里，点'授权'"。两台电脑之间怎么传由用户决定（共享剪贴板、发给自己的消息等）。
   - "对方公钥"输入框和"授权"按钮。Windows 授权需要管理员权限，弹出一次系统确认（内部运行 `setup-sshd.ps1 -PeerPubKey`）；Mac 授权（`authorize`）后提示到系统设置里打开"远程登录"。
   - "测试连接"按钮：用 `request info` 取对方的名字和编码，显示"已连上 <对方>，它接在 <口>"；与第 3 页标记的口不一致时提醒。
5. **完成**："开机自动运行"勾选框（默认勾上）；摘要；"完成"写入配置并开始工作。

## 5. 设置窗口

菜单"设置…"打开。所有改动立刻生效，没有"保存 / 取消"：勾选、选择马上生效；文字框在回车或失去焦点时生效。五个标签页：

1. **输入口**：当前主屏 + "重新检测"（同向导第 2 页）；接口表 + "添加输入口"（同向导第 3 页）。设备的增删、改名在这里做，菜单随之变化。
2. **对方电脑**：同向导第 4 页；另有"不连对方电脑"按钮，清空对方设置。
3. **屏幕**：屏幕组合（自动检测，"重新检测"）；拿回主屏后"扩展屏幕 / 只用主屏"（与菜单同一设置）；"自动记住屏幕排列"勾选框，附说明"在系统设置里拖动两块屏的位置后，自动记住，下次拿回时按这个位置恢复"；"现在记住当前排列"按钮及说明。只有主屏时只显示屏幕组合。
4. **快捷键**：每个动作一行——"切给对方 / 拿回主屏"（同一个键，按当前状态）以及每个设备。默认全空；点输入框后按下组合键即录下，旁边"清除"；注册失败时在该行显示原因。
5. **通用**："开机自动运行"；"重新运行设置向导"；"打开日志"；版本号。折叠的"高级"区："先直接切换"开关（directTake）；"拿回主屏后执行的命令"（仅 Windows，afterTake）；"打开配置文件所在的文件夹"。

两端标签名、项的顺序、说明文字相同。

## 6. 开机自动运行

系统层面的设置，不写进配置文件：Windows 为"启动"文件夹里的 `ScreenSwitch.lnk`（`install.cmd` 现在就会创建）；Mac 为现有的 LaunchAgent。向导和设置窗口里的勾选框创建或删除它们。

## 7. 命令层（给 Agent 和脚本用）

两端命令名、参数、输出相同。Windows：`ScreenSwitchCli.exe <命令>`；Mac：`~/screenctl/screenctl.sh <命令>`。

| 命令 | 作用 |
|---|---|
| `status` | JSON：是否设置过、主屏、本机名字和编码、屏幕组合、对方电脑（是否配置、名字、编码）、设备、托盘 / 后台程序是否在运行、开机自启、需要处理的问题列表 |
| `detect [--main <型号>]` | 检测主屏、本机编码、屏幕组合并写入。只有一块屏能控制时直接用它；几块都能控制时退出码非 0，列出候选，需带 `--main` 重跑 |
| `ports` | JSON：主屏的输入口清单及每个口登记的内容 |
| `peer set --name <名字> --os <windows\|mac> --host <地址> --user <用户名>` | 设置对方电脑 |
| `peer clear` | 清除对方电脑 |
| `peer test` | 连对方取名字和编码（`request info`），JSON 输出；取到编码时写入配置 |
| `pubkey` | 打印本机公钥，没有就先生成 |
| `authorize "<对方公钥>"` | 授权对方。Windows 需要管理员；没有管理员权限时不动手，打印要用户以管理员身份执行的一行 |
| `device add <编码> <名字>` / `device rename <编码> <名字>` / `device remove <编码>` | 设备增删改名；编码为十进制 1–255，不得与本机、对方或已有设备重复 |
| `set <项> <值>` | `owned-layout extend\|main-only`、`auto-save on\|off`、`direct-take on\|off`、`hotkey peer <组合>\|none`、`hotkey <编码> <组合>\|none`、`after-take "<命令>"`（仅 Windows） |
| `autostart on\|off` | 开机自动运行 |

规则：

- 成功退出码 0；失败非 0，并输出一行原因。JSON 只用于 `status`、`ports`、`peer test`。
- 改了配置后自动让常驻程序重新读取：Mac 用现有的 `reload` 命令；Windows 在命令文件里新增只在本机使用的 `reload`（不经过 ssh-gate）。
- 一问一答的 `setup` / `setup devices` 保留，改为调用同一套逻辑。
- 这些命令都不经过 ssh-gate，对方电脑不能调用。

## 8. 中英文

- 所有给人看的文字（菜单、向导、设置窗口、通知、命令的提示）放在仓库里同一份文字表 `i18n/strings.tsv`：每行"编号 制表符 中文 制表符 英文"，可含 `{0}` 这样的占位。两端构建时从它生成各自的资源。
- 语言跟随系统界面语言：以 `zh` 开头用中文，否则英文。
- 日志、JSON 字段名、配置键名不翻译。

## 9. 与现有协议、格式的关系

- 跨机命令（`request give peer / give code <n> / take / info`）和 ssh-gate 放行范围：不变。
- `request info` 的格式：不变。Mac 若读不出显示器的接口清单，可另议在其中新增一个键带上 Windows 读到的清单（新增键，旧版本忽略）。
- `config.json` / `config.sh` 已有字段：不变，最多新增字段。
- 状态文件、命令文件：格式不变；Windows 命令文件新增本机用的 `reload`。

## 10. AGENTS.md

放在仓库根目录，写给任何 AI 助手（不针对特定产品）。README 里提示"可以让你的 AI 助手按 AGENTS.md 安装"。内容：

1. 软件做什么、适用条件。
2. 两端各自的安装步骤：每步的命令，以及用 `status` 的哪个字段确认做成了。
3. 必须停下来交给用户的事：用显示器按钮把主屏切到这台电脑；Windows 的管理员确认；Mac 的"远程登录"开关和通知权限；任何需要在另一台电脑上做的事。
4. 两台电脑之间的交接：一边做完后输出一段固定格式的"交接信息"（名字、系统、地址、用户名、编码、公钥），用户把它贴给另一台电脑上的助手。
5. 最后的联调：请用户看着屏幕，两边各切换一次，再看两边的 `status`。
6. 不许做的事：除指定步骤外不写显示器指令（`ddc-write`）、不关安全设置、不把 SSH 开放到公共网络、不读取或外传用户的私钥。

## 11. 分工与顺序

- Windows：托盘菜单、设置窗口、向导（`ScreenSwitch.exe`）；第 7 节命令；AGENTS.md 的总体部分和 Windows 部分；文字表的建立。
- Mac：菜单栏程序的菜单、设置窗口、向导；`screenctl.sh` 的第 7 节命令；AGENTS.md 的 Mac 部分；确认能否自己读出接口清单。

顺序（两端同时进行）：

1. 文字表与命令层；
2. 右键菜单；
3. 设置窗口；
4. 首次启动向导；
5. AGENTS.md；
6. 两端联调与真机验收。

## 12. 测试与验收

- 命令层和界面背后的逻辑（菜单项的生成、向导每页的校验、设置项的读写）写自动测试，沿用两端现有的测试方式；界面代码只做显示和转发。
- Windows 提供一条命令，把菜单、设置窗口每一页、向导每一页画成图片保存，供不安装就审阅；Mac 端尽量提供截图。
- 真机验收清单：
  1. 全新安装后向导自动出现，走完后能切换；
  2. 在设置里给某个口登记设备、改名，菜单随之变化；
  3. 两边在窗口里互相授权，"测试连接"成功，两边各切换一次；
  4. "扩展屏幕 / 只用主屏"在菜单和设置窗口里一致；
  5. 开机自动运行的开关生效；
  6. 系统语言分别为中文、英文时界面文字正确；
  7. 一个 Agent 只按 AGENTS.md，在用户配合下完成两端安装。
