# 硬件实测笔记

作者开发时用的设备，以及在这些设备上实测到的显示器行为。你的显示器很可能不一样：只在当前输入口回应 DDC、切走后不断开连接、读数不可靠，这些都是型号相关的。欢迎把你的测试结果补充进来（见 README 的“参与”一节）。

## 测试环境

| 设备 | 说明 |
|---|---|
| 共享显示器 | 泰坦军团 2750V（EDID 名 P275MV，厂商码 LHC，产品码 9059），27 英寸 4K 160 Hz，OSD 中 DDC/CI 为“开” |
| Windows 台式机 | Windows 11 Pro，NVIDIA RTX 4070 Ti SUPER；DP 接共享显示器；另接一块 2560×1440 的副屏（只接 Windows） |
| Mac | MacBook Air（M4），USB-C 接共享显示器；系统自带 bash 3.2，Homebrew 的 m1ddc 1.2.0、displayplacer 1.4.0 |
| 其他设备 | Nintendo Switch（第三方底座）接 HDMI 1 |

## 输入源编码（VCP 0x60）

| 输入口 | 编码 |
|---|---|
| USB-C（Mac） | 0x0F（15） |
| DP（Windows） | 0x10（16） |
| HDMI 1 | 0x11（17） |
| HDMI 2 | 0x12（18） |

显示器 capabilities 里 0x60 的可选值是 `11 12 0F 10`。USB-C 口用的是 MCCS 标准里“DisplayPort 1”的编码，所以编码要以实际读到的为准，不要按接口名猜。

## DDC/CI 行为

1. **只在当前输入口回应。** 显示器显示 HDMI 1 时，Windows 从 DP 连发 9 次切回指令，90 秒内全部被忽略，读取也全部失败；Mac 从 USB-C 连发 3 次，8 秒内全部被忽略。所以只有正在显示的那台电脑能用 DDC 把显示器切走；显示器停在游戏机上时，只能按显示器按钮回到电脑。
2. **切走后连接不断开。** Windows 和 macOS 都仍然认为显示器连着，收不到任何事件，桌面继续扩展在看不见的屏幕上。这就是本项目要解决的问题。显示器在另一台电脑上停留一段时间（实测半分钟以上）后，macOS 会把它从显示器列表里移除，切回时重新识别。
3. **Mac 上 m1ddc 的读数不能只看退出码。** 显示器不在 Mac 上时，`get input` 仍然返回退出码 0，值是 0、-7、-102 之类的垃圾；睡眠醒来后甚至可能返回缓存里睡前的旧值 15。所以 Mac 端要求“读到本机编码，并且读到的最大亮度等于 init 时学到的真实值”才算显示器在本机（配置项 `SANITY_MAXLUM`）。
4. **显示器在本机时也偶尔读到垃圾值**（99、90、最大亮度 55 等），通常只持续 1–2 次；刚切到 Mac 的约 3 秒内读数也不可靠。所以 Mac 端连续 4 次读失败才让出，拿回后 3 秒内不读。
5. **同时读会串包。** 两个进程同时读 DDC 时，一方可能收到另一方的回复（读输入源却得到亮度值 90）。Mac 端所有 DDC 访问都经文件锁串行化；其他调亮度的软件同时运行时仍可能串包。

## 显示器的“自动”输入模式

- OSD 里把输入源设为“自动”时，当前口没有信号约 10 秒后，显示器会跳到有信号的口。
- 用 DDC 切到**另一个**口会退出“自动”，固定在那个口；写入**当前**口的编码不会退出。
- “自动”既读不出来，也不能用 DDC 设置：把 capabilities 列出的 33 个码和 0x00–0xFF 中全部 65 个会回应的码都读了一遍，“自动”和“固定 DP”两种状态下读数完全相同；写 `0x60=0x00`、`0x60=0xFF` 都无效。过程见 [ddc-auto-probe.md](ddc-auto-probe.md)。
- 因此经 DDC 切到没有信号的 HDMI 口后，这块显示器通常停在黑屏，1–2 分钟也不跳回。只有一次因为底座 HDMI 握手失败，约 30 秒后跳回。“切给 Other”会依次尝试各个 HDMI 口，这个探测只在显示器会自动跳回时才有用，所以菜单上提示“请先打开设备”。

## 其他观察

- 显示器停在没有信号的 HDMI 口时，会反复“休眠—被唤醒”：显示器重新识别时，Windows 恢复它数据库里保存的显示拓扑，DP 重新握手又把显示器唤醒。只能靠显示器的节能设置缓解。
- UAC 提示框出现期间（它显示在安全桌面上，可能正好在看不见的那块屏上），Windows 拒绝一切显示拓扑修改（`SetDisplayConfig` 返回 5）。所以布局修改失败后每 10 秒自动重试。
- Windows 关闭副屏后，`\\.\DISPLAY2` 下仍列着这块未激活的屏；定位共享显示器时只能数激活的显示器，否则 DDC 句柄下标会错。
- macOS 镜像显示器时默认开启“勿扰”，提示只进通知中心、不弹横幅；可在“系统设置 → 通知”里打开“镜像或共享显示器时允许通知”。
- launchd 启动的后台进程用 `osascript` 发的通知会被 macOS 静默丢弃，所以通知由菜单栏程序发出；菜单栏程序本身要用 `lsregister` 登记过才能发通知。
- `displayplacer` 的 `enabled:false` 能关掉笔记本屏，但之后用任何 ID 都开不回来；本项目改用 CoreGraphics 的未公开函数 `CGSConfigureDisplayEnabled` 开关笔记本屏（只对当前登录会话有效，注销后系统自动恢复）。
- 打开笔记本屏和设镜像不能放在同一个配置事务里：笔记本屏还没打开时设的镜像会被系统丢掉，要等它上线后再设。

## 实测耗时

| 场景 | 耗时 |
|---|---|
| 显示器被切走后 Windows 让出 | 平均约 1.3 秒 |
| 显示器被切走后 Mac 让出 | 约 4.5 秒（为挡住垃圾读数，去抖更严） |
| 按显示器按钮切到 Mac | 显示器黑屏约 3 秒，能读到 DDC 后约 1 秒完成布局 |
| 在 Windows 上按 Ctrl+Alt+1 拿回（经 SSH 请 Mac 切换） | 按下到双屏出现约 7–8 秒，主要花在 SSH、Mac 写 DDC 和显示器切换输入时的黑屏上 |
