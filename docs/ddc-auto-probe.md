# 主屏"输入源：自动"的 DDC 探测记录（只读）

日期：2026-09-23，Windows 端通过 dxva2 执行，主屏 P275MV（LHC9059）在 DP 口活跃时读取。全程只发送 Get VCP Feature / Capabilities Request，未写入任何码。

## Capabilities 原文

```
(prot(monitor)type(lcd)MStarcmds(01 02 03 07 0C E3 F3)vcp(02 04 05 08 10 12 14(05 06 08 0B 0C 0D)16 18 1A 60( 11 12 0F 10) AA(01 02) 62 AC AE B2 B6 C6 C8 C9 CC(01 02 03 04 05 06 07 08 09 0A 0C 0D 0E 0F 14 16 17 19 1E 23 24 25)D6(01 04 05)  DF FD E0 E1 E2 E3 F0 F3 F7 FE FF)mccs_ver(2.1)mswhql(1))
```

## 方法

1. 读取 capabilities 列出的 33 个码；OSD 输入信号为"固定 DP"（上一次由 DDC 0x60 切到 DP 后的状态）读一次，用户在 OSD 设为"自动"后读三次，用户切回"DP"后再读一次。
2. 只读扫描 0x00–0xFF 全部 256 个码，各状态下连续扫两遍以识别噪声：固定 DP 两遍、自动两遍。

共 65 个码回应（33 个列出 + 32 个未列出）。

## 结果

| 对比 | 差异 |
|---|---|
| 列出码：固定 DP → 自动 | 仅 `0xF3`：0xED77 → 0xED79（连读三次稳定） |
| 列出码：自动 → 切回 DP | 仅 `0xF3`：0xED79 → 0xED7E（**没有回到 0xED77**） |
| 全范围：固定 DP 连续两遍 | `0xF3` 0xED80 → 0xED81，`0xFA` 0 ↔ 0x10（什么都没做也在变） |
| 全范围：自动 连续两遍 | 剔除 F3/FA 后零差异 |
| 全范围：固定 DP vs 自动（剔除 F3/FA） | **零差异**，两组各 65 个码读数完全相同 |

`0xF3` 是随时间或 DDC 事务递增的计数器，`0xFA` 自身翻转，二者都与"自动"无关。

**结论：这块显示器的"输入源：自动"设置不通过任何可读的 VCP 码暴露。** 列出的厂商码 0xE0–0xFF 与列表外的 32 个响应码在自动/固定两种状态下读数一致，因此无法通过读取判断当前是否为自动，也没有找到可用于设置"自动"的候选码。

## 下一步可选实验（涉及写入，需用户同意）

唯一低风险的候选是对已知的输入源码 `0x60` 写一个列表外的值来试探"自动"：常见约定是 `0x00` 或 `0xFF`（部分 MStar 方案用 0x00 表示 Auto）。建议在主屏显示 Windows 时从 Windows 执行 `ScreenSwitchCli.exe ddc-write 00`，然后看 OSD 里输入信号是否显示"自动"，并用关 Switch 的方法验证是否跳走；若显示器因此切到别的口，按快捷键 2 切回即可。这是对输入源码的写入，不是未知厂商码，不会触发恢复出厂之类的操作。除此之外不建议写任何 0xE0–0xFF 的值。

## 对设计的影响

在找到可靠的"设自动"方法之前，"切给 Other"后主屏会停在所选口，Other 设备关机后需要按显示器快捷键 2 回到电脑。这与设计文档 4.4 的现有兜底一致。

## 写入试探结果（2026-09-23，用户同意后执行，均在主屏显示 Windows 时从 DP 口写入）

| 前置状态（OSD） | 写入 | 之后 OSD 显示 | 结论 |
|---|---|---|---|
| 自动 | `0x60 = 0x10`（当前口 DP） | 自动 | 写入当前活跃口的编码**不会**退出自动；Mac 端观察到的"写 0x60 退出自动"只在真正切到另一个口时发生 |
| DP（手动固定） | `0x60 = 0x00` | DP | 无效 |
| DP（手动固定） | `0x60 = 0xFF` | DP | 无效 |

三次写入后主屏都留在 DP，读回 0x60 均为 0x10。

**最终结论：这块显示器的"输入源：自动"既不可读也不可通过 DDC 设置。** 可行的使用方式只有两种：
1. 用户在 OSD 里设为"自动"后，只用显示器快捷键 2 切换输入源（不经 DDC），显示器会保持自动模式，Other 设备关机后约 10 秒自动跳回有信号的电脑；但这样两台电脑的"一键切换"就不可用。
2. 继续用 DDC 一键切换，接受"切给 Other 后主屏固定在该口，Other 关机需按快捷键 2 回来"，即设计文档 4.4 的现有兜底。

建议保持方式 2 作为默认，把方式 1 写进 README 作为可选用法。
